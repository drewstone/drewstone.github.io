## Working Thesis

Public self-improvement is not recursive god-mode. It is a stack of increasingly strong loops: reflection, memory, prompt evolution, test-time correction, generated training data, evolutionary search, and production trace mining.

The connective series thesis: long-running tasks are the empirical bottleneck, and self-improvement is the mechanism for crossing it.

## Outline Notes

### Define The Ladder

- Level 0: retry / self-critique.
- Level 1: reflection memory, e.g. Reflexion.
- Level 2: skill libraries, e.g. Voyager.
- Level 3: prompt/program optimization, e.g. GEPA, DSPy/MIPRO.
- Level 4: test-time self-correction trained by RL, e.g. SCoRe.
- Level 5: self-generated fine-tuning/update directives, e.g. SEAL.
- Level 6: algorithm discovery loops, e.g. AlphaEvolve/OpenEvolve.
- Level 7: lab-scale closed loops using proprietary traces, evals, synthetic data, and deployment feedback.

### What's Actually Open

- Reflexion is old but still conceptually important.
- GEPA is a strong public example of trace/reflection-driven prompt evolution.
- SEAL is closer to weight-level adaptation, but still bounded research.
- OpenEvolve shows the AlphaEvolve pattern is not conceptually secret, though frontier-scale execution may be.

### What Frontier Labs Likely Have That Open Source Doesn't

- Massive private trajectory corpora.
- Reliable reward models / graders.
- Production traces.
- Secure sandboxes.
- Human expert labels.
- Compute for repeated rollouts.
- Deployment feedback loops.

### Is Self-Improvement Only Frontier-Lab Magic?

- No for prompt/tool/system improvement.
- Mostly yes for model-weight improvement at frontier scale.
- The interesting middle ground is product teams that use traces -> evals -> prompt/runtime changes -> held-out gates.

### Drew Angle To Rewrite Around

"The self-improving system is not the model. It's the harness."
