## Working Thesis

The industry has moved from "can the model answer?" to "can an agent stay coherent across hours, tools, state, failures, and changing goals?" Current benchmarks show progress, but also expose that long-horizon autonomy is still brittle.

The connective series thesis: we keep talking about "agents" and "superintelligence," but the real substrate is long-horizon reliability plus closed-loop improvement in the real world.

## Outline Notes

### What Counts As Long-Running?

- Not just long context.
- Tasks with compounding state, partial observability, delayed reward, tool errors, and recovery.
- Tie to METR's "task-completion time horizon" framing: human-time duration at which agents succeed reliably.

### Benchmark Landscape

- Software: SWE-Marathon, RALPHBench, SWE-EVO, RoadmapBench, LongCLI-Bench.
- Terminal / ops: Terminal-Bench 2.0, LongCLI-Bench.
- Web / open-world: Odysseys, WebArena lineage.
- Business simulation: YC-Bench, Vending-Bench.
- Memory: Agent Memory Benchmark.

### What The Benchmarks Agree On

- Models fail by losing state, over-parallelizing, misreading environment feedback, stopping early, or optimizing the wrong artifact.
- Long-horizon success is less about one brilliant answer and more about repair loops.

### Open-Source Systems And Tools

- OpenHands for software agents.
- LangGraph / CrewAI / AutoGen / Microsoft Agent Framework / Pydantic AI / Mastra / Agno for orchestration.
- OpenEvolve / CodeEvolve as algorithm-improvement agents.
- Claude Code / Codex / OpenClaw style systems as practical long-session products.

### Industry State

- Frontier labs and coding products are pushing persistent sessions, skills, terminals, browser control, and issue-to-PR workflows.
- But true "leave it alone for a day" reliability is still rare.

### Drew Angle To Rewrite Around

"Long-running agents don't need bigger prompts. They need black-box traces, resumable state, failure taxonomies, and proof protocols."
